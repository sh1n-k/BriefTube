## 기술 스택

- **언어**: Python 3.11+
- **웹 프레임워크**: FastAPI (uvicorn)
- **프론트엔드**: Jinja2 템플릿 + HTMX + Tailwind CSS (CDN)
- **백그라운드 워커**: `asyncio.create_task` + FastAPI lifespan
- **DB**: SQLite (aiosqlite) + FTS5
- **자막 추출**: youtube-transcript-api (v1.0+)
- **영상 다운로드**: yt-dlp (서브프로세스 호출, ffmpeg 필요)
- **LLM**: 오픈클로 API (httpx)
- **알림**: Telegram Bot API (httpx 직접 호출)
- **RSS 파싱**: httpx + `xml.etree.ElementTree`
- **HTTP 클라이언트**: httpx (async) — RSS·텔레그램·오픈클로 공용

### lifespan 패턴

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 시작: stuck 상태 복구 + orphan LLM 후보 복구 + 워커 기동
    recovered = await recover_stuck_jobs(db)
    orphan_repaired = await repository.repair_orphan_llm_candidates(db)
    tasks = [
        asyncio.create_task(run_rss_poller(runtime),        name="rss_poller"),
        asyncio.create_task(run_download_worker(runtime),    name="download_worker"),
        asyncio.create_task(run_transcript_fetcher(runtime), name="transcript_fetcher"),
        asyncio.create_task(run_llm_queue_worker(runtime),   name="llm_queue_worker"),
        asyncio.create_task(run_telegram_notifier(runtime),  name="telegram_notifier"),
    ]
    yield
    # 종료: 워커 정리 + HTTP 클라이언트/DB 닫기
    for t in tasks:
        t.cancel()
    await asyncio.gather(*tasks, return_exceptions=True)
    await http_client.aclose()
    await db.close()
```

### 앱 시작 시 stuck 상태 복구

앱이 비정상 종료되면 진행 중 상태에서 멈춘 레코드가 남을 수 있다. lifespan 시작 시 2가지 복구 실행:

1. **LLM processing → llm_pending 복구**:
```sql
UPDATE videos SET pipeline_status = 'llm_pending'
WHERE pipeline_status = 'llm_processing';
```

2. **Orphan LLM 후보 복구**: 자막은 완료되었으나 `pipeline_status`가 `transcript_pending`에 남아 있는 영상을 `llm_pending`으로 전환

## 백그라운드 워커 명세

모든 워커는 FastAPI lifespan에서 `asyncio.create_task`로 기동되며, 단일 이벤트 루프에서 동작한다.

### RSS Poller
- **주기**: 설정 가능 (기본 15분), `asyncio.sleep`으로 대기
- **동작**:
  1. 전체 활성 채널의 RSS 피드를 `httpx.AsyncClient`로 비동기 조회
  2. `xml.etree.ElementTree`로 YouTube Atom 피드 파싱 (네임스페이스: `yt:`, `media:`, `atom:`)
  3. 기존 DB에 없는 video_id 발견 시 videos 테이블에 INSERT (`pipeline_status='transcript_pending'`)
  4. 채널의 `last_seen_published_at` 워터마크를 최신 영상의 published 시각으로 갱신
  5. RSS 404 응답 시 채널 자동 비활성화 + `system_alerts`에 알림 생성
- **캐시**: ETag/Last-Modified로 304 응답 활용, 불필요한 처리 방지
- **즉시 트리거**: `poll_now_event` (asyncio.Event)로 API에서 즉시 폴링 가능

#### YouTube Atom 피드 파싱

```python

NAMESPACES = {
    "atom": "http://www.w3.org/2005/Atom",
    "yt": "http://www.youtube.com/xml/schemas/2015",
    "media": "http://search.yahoo.com/mrss/",
}

async def fetch_youtube_feed(client: httpx.AsyncClient, channel_id: str):
    url = f"https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}"
    resp = await client.get(url)
    root = fromstring(resp.text)
    return [
        {
            "video_id": entry.find("yt:videoId", NAMESPACES).text,
            "title": entry.find("atom:title", NAMESPACES).text,
            "published": entry.find("atom:published", NAMESPACES).text,
            "thumbnail": entry.find("media:group/media:thumbnail", NAMESPACES).get("url"),
        }
        for entry in root.findall("atom:entry", NAMESPACES)
    ]
```

### Transcript Fetcher
- **트리거**: videos 테이블에서 `pipeline_status='transcript_pending'`인 레코드
- **동작**: youtube-transcript-api (v1.0+)로 자막 추출 → transcripts에 INSERT, `pipeline_status='llm_pending'` 업데이트. 자막 없으면 `pipeline_status='no_subtitle'`
- 썸네일도 이 단계에서 다운로드하여 로컬 저장
- **async 통합**: youtube-transcript-api는 동기 라이브러리이므로 `asyncio.to_thread()`로 래핑
- **Transcript Guard**: 429/403 시 adaptive factor 증가 + hard cooldown, 연속 성공 시 factor 감소. 상태는 `app_settings` KV 테이블에 영속화
- **채널 레벨 쿨다운**: 같은 채널에 연속 요청하지 않도록 채널별 최소 간격 (`transcript_channel_min_interval_seconds`) 적용

```python
ytt_api = YouTubeTranscriptApi()

async def fetch_transcript(video_id: str):
    transcript = await asyncio.to_thread(ytt_api.fetch, video_id)
    return transcript.to_raw_data()
```

#### 자막 Fallback 전략

현재 1차(youtube-transcript-api)만 구현. `no_subtitle` 영상의 실제 발생 빈도를 관찰한 후 필요 시 다음 단계를 추가한다:

```
1차: youtube-transcript-api    (비용 $0, 빠름)
  ↓ 실패 시
2차: yt-dlp 자막 추출            (비용 $0, 영상 다운로드 없이 자막만)
  ↓ 실패 시
3차: 오디오 → gpt-4o-mini-transcribe  ($0.003/분, GPU 불필요)
```

### LLM Queue Worker
- **트리거**: `pipeline_status='llm_pending'`인 레코드
- **동작**:
  1. `pipeline_status='llm_processing'`으로 업데이트
  2. 프롬프트 템플릿에 자막 텍스트를 삽입하여 오픈클로 API 호출 (`httpx.AsyncClient`)
  3. 성공 시: 응답 파싱하여 articles에 INSERT, `pipeline_status='done'`
  4. 실패 시: retry_count 증가, `pipeline_status='llm_failed'`. `retry_count < 3`이면 다음 사이클에 재시도. `retry_count >= 3`이면 `pipeline_status='manual_review'`
- **토큰 초과 대비**: 자막 길이가 임계치를 넘으면 청크 분할 후 순차 호출, 결과 병합

### Download Worker
- **트리거**: `download_jobs` 테이블에서 `status='pending'`인 작업
- **동작**:
  1. 대기 중인 다운로드 작업을 claim하여 `status='running'` 전환
  2. yt-dlp를 asyncio 서브프로세스로 실행하여 영상 다운로드
  3. 성공 시: 출력 파일 경로·크기 기록, `status='done'`
  4. 실패 시: 에러 코드 분류 (ffmpeg_missing, http_403, timeout 등), `status='failed'`
- **동시성**: `download_max_concurrent` (기본 2, 최대 3)만큼 동시 다운로드
- **깨우기**: `download_wake_event` (asyncio.Event)로 새 작업 등록 시 즉시 시작
- **품질 옵션**: 2160/1440/1080/720/480 중 선택, 기본 1080p

### Telegram Notifier
- **트리거**: LLM 워커가 `notification_queue`에 넣은 완성 기사
- **구현**: `httpx.AsyncClient`로 Telegram Bot API `sendMessage` 직접 호출
- **메시지 포맷**:
  ```
  📰 [기사 제목]
  ---
  [리드 3줄 요약]
  🔗 https://youtube.com/watch?v={video_id}
  ```
- 배치 내 여러 건이면 하나의 메시지로 묶어 발송

```python
class TelegramNotifier:
    BASE_URL = "https://api.telegram.org/bot{token}"

    def __init__(self, token: str, chat_id: str, client: httpx.AsyncClient):
        self.url = self.BASE_URL.format(token=token) + "/sendMessage"
        self.chat_id = chat_id
        self.client = client

    async def send(self, text: str, parse_mode: str = "HTML") -> dict:
        resp = await self.client.post(
            self.url,
            json={"chat_id": self.chat_id, "text": text, "parse_mode": parse_mode},
        )
        resp.raise_for_status()
        return resp.json()
```

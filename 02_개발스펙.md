## 기술 스택

- **언어**: Python 3.11+
- **웹 프레임워크**: FastAPI (uvicorn)
- **프론트엔드**: Jinja2 템플릿 + HTMX + Tailwind CSS (CDN)
- **백그라운드 워커**: `asyncio.create_task` + FastAPI lifespan
- **DB**: SQLite (aiosqlite) + FTS5
- **자막 추출**: youtube-transcript-api (v1.0+)
- **LLM**: 오픈클로 API (httpx)
- **알림**: Telegram Bot API (httpx 직접 호출)
- **RSS 파싱**: httpx + `xml.etree.ElementTree`
- **HTTP 클라이언트**: httpx (async) — RSS·텔레그램·오픈클로 공용

## 라우트 분리 원칙

React 전환을 대비하여 라우트를 명확히 분리한다:

- `/api/*` — JSON 응답 전용. 프론트엔드 프레임워크와 무관하게 유지
- `/views/*` — HTMX용 HTML 조각 응답. Jinja2 템플릿 렌더링
- `/` , `/videos/*`, `/channels/*` — 전체 페이지 렌더링 (Jinja2 레이아웃)

React 전환 시: `/views/*`와 페이지 라우트만 제거하고, React 앱이 `/api/*`를 호출하도록 교체하면 된다.

### lifespan 패턴

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # 시작: stuck 상태 복구 + 워커 기동
    await recover_stuck_jobs(db)
    tasks = [
        asyncio.create_task(rss_poll_loop()),
        asyncio.create_task(transcript_fetch_loop()),
        asyncio.create_task(llm_queue_loop()),
    ]
    yield
    # 종료: 워커 정리
    for t in tasks:
        t.cancel()

app = FastAPI(lifespan=lifespan)
```

## DB 스키마

```sql
CREATE TABLE channels (
    channel_id              TEXT PRIMARY KEY,           -- YouTube channel ID
    channel_name            TEXT NOT NULL,
    rss_url                 TEXT NOT NULL,              -- https://www.youtube.com/feeds/videos.xml?channel_id=XXX
    is_active               INTEGER NOT NULL DEFAULT 1, -- 1=구독중, 0=해지
    last_seen_published_at  TEXT,                       -- 워터마크: 마지막으로 확인한 영상의 published 시각 (ISO 8601)
    created_at              TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE videos (
    video_id            TEXT PRIMARY KEY,    -- YouTube video ID
    channel_id          TEXT NOT NULL REFERENCES channels(channel_id),
    title               TEXT NOT NULL,
    upload_time         TEXT NOT NULL,       -- ISO 8601
    thumbnail_path      TEXT,               -- 로컬 파일 경로
    transcript_status   TEXT NOT NULL DEFAULT 'pending',
        -- pending | done | no_subtitle
    restructure_status  TEXT NOT NULL DEFAULT 'pending',
        -- pending | processing | done | failed | manual_review
    retry_count         INTEGER NOT NULL DEFAULT 0,
    created_at          TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE transcripts (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id    TEXT NOT NULL UNIQUE REFERENCES videos(video_id),
    raw_text    TEXT NOT NULL,
    language    TEXT,                        -- ko, en, etc.
    source_type TEXT NOT NULL,               -- manual | auto
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE articles (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id    TEXT NOT NULL UNIQUE REFERENCES videos(video_id),
    title       TEXT NOT NULL,               -- 재작성된 기사 제목
    lead        TEXT NOT NULL,               -- 3줄 요약
    body        TEXT NOT NULL,               -- 주장-근거-사례-결론
    fact_box    TEXT,                        -- JSON: 숫자/고유명사/용어
    timestamps  TEXT,                        -- JSON: [{time, label}]
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 전문 검색 인덱스
CREATE VIRTUAL TABLE transcripts_fts USING fts5(raw_text, content=transcripts, content_rowid=id);
CREATE VIRTUAL TABLE articles_fts USING fts5(title, lead, body, content=articles, content_rowid=id);

-- FTS5 동기화 트리거: transcripts
CREATE TRIGGER transcripts_ai AFTER INSERT ON transcripts BEGIN
    INSERT INTO transcripts_fts(rowid, raw_text) VALUES (new.id, new.raw_text);
END;
CREATE TRIGGER transcripts_ad AFTER DELETE ON transcripts BEGIN
    INSERT INTO transcripts_fts(transcripts_fts, rowid, raw_text) VALUES ('delete', old.id, old.raw_text);
END;
CREATE TRIGGER transcripts_au AFTER UPDATE ON transcripts BEGIN
    INSERT INTO transcripts_fts(transcripts_fts, rowid, raw_text) VALUES ('delete', old.id, old.raw_text);
    INSERT INTO transcripts_fts(rowid, raw_text) VALUES (new.id, new.raw_text);
END;

-- FTS5 동기화 트리거: articles
CREATE TRIGGER articles_ai AFTER INSERT ON articles BEGIN
    INSERT INTO articles_fts(rowid, title, lead, body) VALUES (new.id, new.title, new.lead, new.body);
END;
CREATE TRIGGER articles_ad AFTER DELETE ON articles BEGIN
    INSERT INTO articles_fts(articles_fts, rowid, title, lead, body) VALUES ('delete', old.id, old.title, old.lead, old.body);
END;
CREATE TRIGGER articles_au AFTER UPDATE ON articles BEGIN
    INSERT INTO articles_fts(articles_fts, rowid, title, lead, body) VALUES ('delete', old.id, old.title, old.lead, old.body);
    INSERT INTO articles_fts(rowid, title, lead, body) VALUES (new.id, new.title, new.lead, new.body);
END;

-- 조회 성능 인덱스
CREATE INDEX idx_videos_channel ON videos(channel_id);
CREATE INDEX idx_videos_upload ON videos(upload_time DESC);
CREATE INDEX idx_videos_restructure ON videos(restructure_status) WHERE restructure_status IN ('pending', 'processing', 'failed');
```

## 백그라운드 워커 명세

모든 워커는 FastAPI lifespan에서 `asyncio.create_task`로 기동되며, 단일 이벤트 루프에서 동작한다.

### RSS Poller
- **주기**: 설정 가능 (기본 15분), `asyncio.sleep`으로 대기
- **동작**:
  1. 전체 활성 채널의 RSS 피드를 `httpx.AsyncClient`로 비동기 조회
  2. `xml.etree.ElementTree`로 YouTube Atom 피드 파싱 (네임스페이스: `yt:`, `media:`, `atom:`)
  3. 기존 DB에 없는 video_id 발견 시 videos 테이블에 INSERT (`transcript_status=pending`)
  4. 채널의 `last_seen_published_at` 워터마크를 최신 영상의 published 시각으로 갱신
- **RSS URL 형식**: `https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}`
- RSS 피드는 최근 15개만 반환하므로 주기가 지나치게 길면 누락 가능. 워터마크로 마지막 확인 시점을 추적

#### YouTube Atom 피드 파싱

```python
from xml.etree.ElementTree import fromstring

NAMESPACES = {
    "atom": "http://www.w3.org/2005/Atom",
    "yt": "http://www.youtube.com/xml/schemas/2015",
    "media": "http://search.yahoo.com/mrss/",
}

async def fetch_youtube_feed(client: httpx.AsyncClient, channel_id: str):
    url = f"https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}"
    resp = await client.get(url)
    root = fromstring(resp.text)
    return [
        {
            "video_id": entry.find("yt:videoId", NAMESPACES).text,
            "title": entry.find("atom:title", NAMESPACES).text,
            "published": entry.find("atom:published", NAMESPACES).text,
            "thumbnail": entry.find("media:group/media:thumbnail", NAMESPACES).get("url"),
        }
        for entry in root.findall("atom:entry", NAMESPACES)
    ]
```

### Transcript Fetcher
- **트리거**: videos 테이블에서 `transcript_status=pending`인 레코드
- **동작**: youtube-transcript-api (v1.0+)로 자막 추출 → transcripts에 INSERT, `transcript_status=done` 업데이트. 자막 없으면 `transcript_status=no_subtitle`
- 썸네일도 이 단계에서 다운로드하여 로컬 저장
- **async 통합**: youtube-transcript-api는 동기 라이브러리이므로 `asyncio.to_thread()`로 래핑

```python
ytt_api = YouTubeTranscriptApi()

async def fetch_transcript(video_id: str):
    transcript = await asyncio.to_thread(ytt_api.fetch, video_id)
    return transcript.to_raw_data()
```

#### 자막 Fallback 전략

Phase 2에서는 1차(youtube-transcript-api)만 구현한다. `no_subtitle` 영상의 실제 발생 빈도를 관찰한 후 필요 시 다음 단계를 추가한다:

```
1차: youtube-transcript-api    (비용 $0, 빠름)
  ↓ 실패 시
2차: yt-dlp 자막 추출            (비용 $0, 영상 다운로드 없이 자막만)
  ↓ 실패 시
3차: 오디오 → gpt-4o-mini-transcribe  ($0.003/분, GPU 불필요)
```

### LLM Queue Worker
- **트리거**: `transcript_status=done AND restructure_status=pending`인 레코드
- **동작**:
  1. `restructure_status=processing`으로 업데이트
  2. 프롬프트 템플릿에 자막 텍스트를 삽입하여 오픈클로 API 호출 (`httpx.AsyncClient`)
  3. 성공 시: 응답 파싱하여 articles에 INSERT, `restructure_status=done`
  4. 실패 시: retry_count 증가, `restructure_status=failed`. `retry_count < 3`이면 다음 사이클에 재시도. `retry_count >= 3`이면 `restructure_status=manual_review`
- **토큰 초과 대비**: 자막 길이가 임계치를 넘으면 청크 분할 후 순차 호출, 결과 병합

### Telegram Notifier
- **트리거**: 하나의 폴링 배치에서 LLM 처리가 모두 완료된 시점
- **구현**: `httpx.AsyncClient`로 Telegram Bot API `sendMessage` 직접 호출
- **메시지 포맷**:
  ```
  📰 [기사 제목]
  ---
  [리드 3줄 요약]
  🔗 https://youtube.com/watch?v={video_id}
  ```
- 배치 내 여러 건이면 하나의 메시지로 묶어 발송

```python
class TelegramNotifier:
    BASE_URL = "https://api.telegram.org/bot{token}"

    def __init__(self, token: str, chat_id: str, client: httpx.AsyncClient):
        self.url = self.BASE_URL.format(token=token) + "/sendMessage"
        self.chat_id = chat_id
        self.client = client

    async def send(self, text: str, parse_mode: str = "HTML") -> dict:
        resp = await self.client.post(
            self.url,
            json={"chat_id": self.chat_id, "text": text, "parse_mode": parse_mode},
        )
        resp.raise_for_status()
        return resp.json()
```

## 개발 태스크 (순서대로)

### Phase 1: 기반
1. 프로젝트 초기화 (FastAPI, 의존성 5개 설치)
2. SQLite DB 스키마 생성 (테이블 + FTS5 + 동기화 트리거 + 인덱스)
3. 설정 파일 로딩
4. httpx.AsyncClient 공유 인스턴스 + lifespan 뼈대

### Phase 2: 백그라운드 서비스
5. RSS Poller 구현 (httpx + ET 파싱 + 워터마크)
6. Transcript Fetcher 구현 (youtube-transcript-api v1.0+ / asyncio.to_thread)
7. LLM Queue Worker 구현 (오픈클로 API 연동)
8. Telegram Notifier 구현 (httpx 직접 호출)

### Phase 3: 웹 API + 프론트엔드
9. REST API 엔드포인트 구현
10. 프론트엔드 (영상 목록, 자막 조회, 구독 관리, 검색)

### Phase 4: 통합
11. lifespan 통합 기동 (stuck 복구 + 워커 시작/종료)
12. 엣지 케이스 처리 (자막 없음, 긴 자막 분할, 네트워크 오류)

## 확장 경로

현재 구성은 단일 사용자 로컬 앱·테이블 4개·워커 4개에 최적화되어 있다. 규모 변경 시:

- **다중 인스턴스/분산 처리 필요 시**: asyncio.create_task를 arq(Redis) 또는 Taskiq로 교체, 상태 컬럼을 jobs 테이블 + lease 패턴으로 분리
- **채널 수 대폭 증가 시**: YouTube Data API v3 병행 도입으로 RSS 15건 제한 회피

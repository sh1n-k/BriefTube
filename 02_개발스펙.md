# 개발 스펙

## 기술 스택

- **언어**: Python 3.11+
- **웹 프레임워크**: FastAPI (uvicorn)
- **프론트엔드**: Jinja2 템플릿 + HTMX + Tailwind CSS (CDN)
- **백그라운드 스케줄러**: APScheduler
- **DB**: SQLite (aiosqlite) + FTS5
- **자막 추출**: youtube-transcript-api
- **LLM**: 오픈클로 API (httpx)
- **알림**: python-telegram-bot
- **RSS 파싱**: feedparser
- **HTTP 클라이언트**: httpx (async)

## 라우트 분리 원칙

React 전환을 대비하여 라우트를 명확히 분리한다:

- `/api/*` — JSON 응답 전용. 프론트엔드 프레임워크와 무관하게 유지
- `/views/*` — HTMX용 HTML 조각 응답. Jinja2 템플릿 렌더링
- `/` , `/videos/*`, `/channels/*` — 전체 페이지 렌더링 (Jinja2 레이아웃)

React 전환 시: `/views/*`와 페이지 라우트만 제거하고, React 앱이 `/api/*`를 호출하도록 교체하면 된다.

## DB 스키마

```sql
CREATE TABLE channels (
    channel_id   TEXT PRIMARY KEY,           -- YouTube channel ID
    channel_name TEXT NOT NULL,
    rss_url      TEXT NOT NULL,              -- https://www.youtube.com/feeds/videos.xml?channel_id=XXX
    is_active    INTEGER NOT NULL DEFAULT 1, -- 1=구독중, 0=해지
    created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE videos (
    video_id            TEXT PRIMARY KEY,    -- YouTube video ID
    channel_id          TEXT NOT NULL REFERENCES channels(channel_id),
    title               TEXT NOT NULL,
    upload_time         TEXT NOT NULL,       -- ISO 8601
    thumbnail_path      TEXT,               -- 로컬 파일 경로
    transcript_status   TEXT NOT NULL DEFAULT 'pending',
        -- pending | done | no_subtitle
    restructure_status  TEXT NOT NULL DEFAULT 'pending',
        -- pending | processing | done | failed | manual_review
    retry_count         INTEGER NOT NULL DEFAULT 0,
    created_at          TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE transcripts (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id    TEXT NOT NULL UNIQUE REFERENCES videos(video_id),
    raw_text    TEXT NOT NULL,
    language    TEXT,                        -- ko, en, etc.
    source_type TEXT NOT NULL,               -- manual | auto
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE articles (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id    TEXT NOT NULL UNIQUE REFERENCES videos(video_id),
    title       TEXT NOT NULL,               -- 재작성된 기사 제목
    lead        TEXT NOT NULL,               -- 3줄 요약
    body        TEXT NOT NULL,               -- 주장-근거-사례-결론
    fact_box    TEXT,                        -- JSON: 숫자/고유명사/용어
    timestamps  TEXT,                        -- JSON: [{time, label}]
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 전문 검색 인덱스
CREATE VIRTUAL TABLE transcripts_fts USING fts5(raw_text, content=transcripts, content_rowid=id);
CREATE VIRTUAL TABLE articles_fts USING fts5(title, lead, body, content=articles, content_rowid=id);

-- 조회 성능 인덱스
CREATE INDEX idx_videos_channel ON videos(channel_id);
CREATE INDEX idx_videos_upload ON videos(upload_time DESC);
CREATE INDEX idx_videos_restructure ON videos(restructure_status) WHERE restructure_status IN ('pending', 'processing', 'failed');
```

## REST API (JSON 전용 — `/api/*`)

### 채널 관리

```
GET    /api/channels                    → 구독 채널 목록
POST   /api/channels                    → 채널 추가 { channel_id, channel_name }
DELETE /api/channels/:channel_id        → 채널 해지 (is_active=0)
```

### 영상 조회

```
GET    /api/videos                      → 영상 목록 (쿼리: channel_id, sort=upload_time|created_at, order=asc|desc, page, limit)
GET    /api/videos/:video_id            → 영상 상세 (메타데이터 + 자막 + 기사)
GET    /api/videos/:video_id/transcript → 원본 자막
GET    /api/videos/:video_id/article    → 재구성된 기사
```

### 검색

```
GET    /api/search?q=키워드              → FTS5 전문 검색 (자막 + 기사 통합)
```

### 시스템

```
POST   /api/poll/trigger                → 수동 폴링 트리거
GET    /api/status                      → 큐 현황 (pending/processing/failed 카운트)
POST   /api/videos/:video_id/retry      → 실패한 재구성 수동 재시도
```

## HTMX 뷰 라우트 (`/views/*` — HTML 조각 응답)

React 전환 시 이 섹션 전체를 제거한다.

```
GET    /views/channel-list              → 채널 목록 HTML 조각
GET    /views/video-list?channel_id=&sort=  → 영상 목록 HTML 조각
GET    /views/video-detail/:video_id    → 영상 상세 HTML 조각
GET    /views/search-results?q=         → 검색 결과 HTML 조각
GET    /views/status-badge/:video_id    → 재구성 상태 배지 HTML 조각
```

## 페이지 라우트 (전체 페이지 — Jinja2 레이아웃)

React 전환 시 이 섹션도 제거하고, FastAPI는 정적 파일(React 빌드)을 서빙한다.

```
GET    /                                → 메인 (영상 목록 페이지)
GET    /videos/:video_id               → 영상 상세 페이지
GET    /channels                        → 구독 관리 페이지
```

## 백그라운드 워커 명세

### RSS Poller
- **주기**: 설정 가능 (기본 15분)
- **동작**: 전체 활성 채널의 RSS 피드를 비동기로 조회 → 기존 DB에 없는 video_id 발견 시 videos 테이블에 INSERT (transcript_status=pending)
- **RSS URL 형식**: `https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}`
- RSS 피드는 최근 15개만 반환하므로 주기가 지나치게 길면 누락 가능

### Transcript Fetcher
- **트리거**: videos 테이블에서 transcript_status=pending인 레코드
- **동작**: youtube-transcript-api로 자막 추출 → transcripts에 INSERT, transcript_status=done 업데이트. 자막 없으면 transcript_status=no_subtitle
- 썸네일도 이 단계에서 다운로드하여 로컬 저장

### LLM Queue Worker
- **트리거**: transcript_status=done AND restructure_status=pending인 레코드
- **동작**:
  1. restructure_status=processing으로 업데이트
  2. 프롬프트 템플릿에 자막 텍스트를 삽입하여 오픈클로 API 동기 호출
  3. 성공 시: 응답 파싱하여 articles에 INSERT, restructure_status=done
  4. 실패 시: retry_count 증가, restructure_status=failed. retry_count < 3이면 다음 사이클에 재시도. retry_count >= 3이면 restructure_status=manual_review
- **토큰 초과 대비**: 자막 길이가 임계치를 넘으면 청크 분할 후 순차 호출, 결과 병합

### Telegram Notifier
- **트리거**: 하나의 폴링 배치에서 LLM 처리가 모두 완료된 시점
- **메시지 포맷**:
  ```
  📰 [기사 제목]
  ---
  [리드 3줄 요약]
  🔗 https://youtube.com/watch?v={video_id}
  ```
- 배치 내 여러 건이면 하나의 메시지로 묶어 발송

## 개발 태스크 (순서대로)

### Phase 1: 기반
1. 프로젝트 초기화 (프레임워크, 의존성)
2. SQLite DB 스키마 생성 및 마이그레이션
3. 설정 파일 로딩

### Phase 2: 백그라운드 서비스
4. RSS Poller 구현
5. Transcript Fetcher 구현
6. LLM Queue Worker 구현 (오픈클로 API 연동)
7. Telegram Notifier 구현

### Phase 3: 웹 API + 프론트엔드
8. REST API 엔드포인트 구현
9. 프론트엔드 (영상 목록, 자막 조회, 구독 관리, 검색)

### Phase 4: 통합
10. 백그라운드 스케줄러와 웹 서버 통합 기동
11. 엣지 케이스 처리 (자막 없음, 긴 자막 분할, 네트워크 오류)
